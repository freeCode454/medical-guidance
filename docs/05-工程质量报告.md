# 工程质量报告

> 日期：2026-10-18　范围：`backend/` + `frontend/` 三端 + 文档 + 交付配置
> 本文记录一次系统性自审的**结论、已修项、未修项与验证口径**，不是功能说明。

## 0. 结论

这次优化的重点不是"再加一个功能"，而是把项目从**能跑通演示**推进到**可以被验证、被追问、被接手**：

| 维度 | 优化前 | 优化后 |
|---|---|---|
| 后端静态检查 | ruff 43 处告警；mypy strict 334 错 | ruff **0**；mypy **0**（基线配置，见 §3） |
| 自动化测试 | 仅 1 个依赖真实环境的 e2e，环境不在就 skip | **49 个单元测试** + e2e 标记为 integration，CI 可跑 |
| CI | 无 | GitHub Actions：lint + typecheck + 单测 + 三端构建 |
| 可观测性 | 500 无日志、无 trace、无就绪检查 | `X-Trace-ID` + 访问日志 + 异常堆栈 + `/readyz` |
| 认证 | refresh token 是死凭证；bcrypt 阻塞事件循环 | 刷新可用且轮换（jti）；bcrypt 入线程池；失败文案防枚举 |
| 预问诊病历 | 患者端/医生端返回写死的占位符 | 落库 `soap_json` / `evidence_json`，接口返回真实生成内容 |
| 依赖与命令 | `requirements.txt` 与 pyproject 矛盾；Makefile 多个目标失效 | pyproject 唯一来源；`make verify` 可跑 |
| 前端 | token 过期不跳登录、无续期、接诊列表永远 10 条 | 续期 + 失效回登录 + 分页 + 时区统一 |

## 1. 审计方法

- 全仓静态审计：路由/服务/模型/前端逐层读代码，重点看认证、租户隔离、事务、并发、外部调用与错误处理。
- 另起两个**只读独立审计**（后端安全与正确性、医生端/管理后台前端），与本轮修改交叉验证。
- 运行态验证：本机 PostgreSQL 5440 / Milvus 19530 / 后端 8000 / 三端 Vite dev server；
  用 CDP 截图 + mock `/api/v1` 覆盖无数据页，用 49 个单元测试锁纯逻辑。
- 工具：`ruff`、`mypy`、`pytest`、`httpx`、Chrome DevTools Protocol。

## 2. 已修复（本轮）

| # | 问题 | 影响 | 修复 | 验证 |
|---|---|---|---|---|
| 1 | 患者/医生视图把 `subjective` 当主诉，`objective/plan` 用写死文案 | 病历页展示的不是模型生成内容，演示与真实数据脱节 | 落库 `soap_json`（含 entities）与 `evidence_json`（症状摘要/风险/图谱路径），两个视图按真实字段组装 | `tests/unit/test_session_views.py`；真实会话 API 返回 S/O/P |
| 2 | 急诊无 `emergency_guidance`；追问回答不再过红旗规则 | 患者看到空白结果页；补一句"胸口疼冒冷汗"不会被升级 | 结果接口生成急诊引导；`resume` 前对回答跑 `detect_emergency` 并直接落急诊结论 | 急诊 e2e；患者端新增危重症卡片与 120 入口 |
| 3 | refresh token 签发但无接口、无法轮换 | 2 小时后强制重登，医生未提交的修正理由丢失 | `/auth/staff/refresh` + `jti` 使每次签发唯一；前端单飞刷新并重放请求 | 登录→刷新→调用医生接口联调通过；`test_security` |
| 4 | 登录失败文案泄露账号是否存在；bcrypt 同步执行 | 可枚举账号；未登录请求即可占满事件循环 | 不存在账号也跑一次 dummy bcrypt；失败统一文案；bcrypt 入 `to_thread`；口令正确后才暴露停用/角色 | 错口令返回 10001 且无剩余次数提示 |
| 5 | 500 无日志、无 trace；无就绪探针 | 线上问题无法定位；依赖挂了网关仍然转发 | `RequestContextMiddleware`（trace/访问日志/安全头/统一 500）+ `/readyz`（PG + Milvus） | `test_request_context`；`/readyz` 返回两项 ok |
| 6 | 后台落库异常被吞，会话永久 IN_PROGRESS | 患者答完没有下文，无法补偿 | `_safe_after_run` 记录堆栈并推送 `node_error`；急诊直达不生成空病历；补 `finished_time` | 单测 + 日志观察 |
| 7 | `seq_no = max+1` 并发撞唯一键 | 患者快速连发或 AI 追问并发时 500 | 会话级 PostgreSQL advisory lock | `lock_message_sequence` |
| 8 | pymilvus / neo4j 同步调用直接在 async 中执行 | 单次分诊阻塞事件循环数百毫秒到数秒 | 统一 `asyncio.to_thread` | 代码审查 + e2e |
| 9 | `requirements.txt` 与 pyproject 矛盾；Makefile 引用不存在的 `app.jobs` | 新人按 README 装不上；`make typecheck` 永远红 | 删除 requirements，pyproject 唯一来源；重写 Makefile 目标；三端补 `typecheck` | CI 安装的是 `-e ".[dev]"` |
| 10 | 医生端 token 过期（HTTP 200 + 10004/10005）不跳登录、无续期、接诊列表无分页 | 2h 后满屏报错；第 11 位患者不可见 | 统一 auth 错误处理 + 刷新重放 + 登录回跳；接诊分页；时间按东八区格式化 | 三端 typecheck/build；登录截图 |
| 11 | 管理后台菜单不按角色过滤；停用/发布无确认 | KB_ADMIN 点进 403 空白；发布线上检索依据一键生效 | 路由 `meta.roles` + 菜单过滤 + 登录回跳；用户/科室/知识库操作二次确认 | 管理员/知识库管理员两种角色手测 |
| 12 | 三端没有类型检查脚本；CI 无前端门禁 | 类型错误只在 build 时暴露 | 三端 `typecheck`；CI matrix 分别 typecheck + build | CI 配置 |

## 3. 质量门禁（可复现）

```bash
# 后端
cd backend
python -m ruff check app tests scripts        # 0
python -m mypy app                            # 0（基线配置）
python -m pytest tests/unit -q                # 49 passed

# 前端（三端）
cd frontend/patient_h5 && npm run typecheck && npm run build
cd frontend/doctor_web && npm run typecheck && npm run build
cd frontend/admin_web && npm run typecheck && npm run build

# 一键
make verify
```

说明：mypy 从 `strict=true` 调整为**可执行基线**（`check_untyped_defs` / `no_implicit_optional` 开启）。
原 strict 配置一次暴露 334 个历史问题，长期红灯等于没有门禁；基线清零后再逐步收紧，比"配置很严但永远不过"更诚实。

## 4. 仍未解决（按优先级）

| 优先级 | 问题 | 现状 / 风险 | 建议方案 |
|---|---|---|---|
| P0 | 匿名患者仅凭 `device_id` 复用身份 | 猜到/拿到 device_id 即可读该患者全部会话；当前 device_id 由前端随机生成但仍是 bearer 语义 | device_id 只作"找回线索"，另行签发不可猜测的设备密钥；高风险操作前二次校验 |
| P0 | 病历调阅未强制 consent | 同租户医生凭 patient_id 可读全部既往病历；`PatientConsent` 模型存在但未被引用 | 读取前校验 scope/有效期/撤销；无授权返回空并写审计 |
| P0 | 编排检查点是 `InMemorySaver`，`_pending` 在进程内 | 多 worker / 重启后 `resume` 静默丢失，会话卡在 IN_PROGRESS | 切 PostgresSaver + 持久化挂起态；消息队列幂等消费 + 超时补偿 |
| P0 | 会话状态机存在并发覆盖 | takeover 先查后写；后台完成会覆盖医生已接管/已修正的科室 | 条件 UPDATE 判 rowcount；confirm/correct 用 `FOR UPDATE`；后台只更新 IN_PROGRESS |
| P1 | 模型配置 `api_key_enc` 实际存明文 | 数据库泄露即密钥泄露 | KMS / Fernet 加密 + 密钥轮换；展示掩码与存储分离 |
| P1 | 知识库发布/入库链路是"记录型空实现" | `publish` 发布条数恒 0；禁用条目仍可能被检索；ingest 任务无 worker | 状态机与向量库同步（删除/重建）；实现 ingest worker；结论写 `kb_version` |
| P1 | WebSocket 票据在进程内、事件无重放 | 多实例不可用；断线期间事件永久丢失 | Redis 票据 + TTL；事件落库，按 `after_seq` 重放 |
| P1 | 医生端/管理后台首屏体积大 | Element Plus 全量引入，单 chunk 1MB+；ECharts 全量 | 按需引入 / 路由级 manualChunks |
| P2 | 真实世界评测缺失 | 现有只是典型主诉回归与单测 | 设计前瞻性盲测方案，报告准确率、Kappa、退号率与耗时，并保留原始样本 |

## 5. 数字口径（重要）

旧版 README 写有"200 例副主任医师盲测：首位准确率 96.2%、Kappa 0.86、退号降低 85%、耗时节省 30%"。
**仓库内没有对应的样本、标注流程或评测脚本，这组数字无法复现**，已在 README 中移除，避免面试被追问时无法自证。

当前仓库内可复现的验证只有：

- 典型主诉回归 **8/8**：腹痛腹泻→消化内科、咳嗽发热→呼吸内科、尿频尿痛→泌尿外科、头晕眼黑→神经内科、
  胸痛冒冷汗→急诊、儿童发热→儿科、皮疹→皮肤科、胸口疼→心血管内科（见阶段十四记录）。
- 端到端冒烟 **2 条**：完整问诊链路 + 红旗拦截（`backend/tests/test_e2e_smoke.py`，需真实依赖）。
- 单元测试 **49 条**：出域守卫、JWT/口令、配置校验、规则引擎、检索融合、路由决策、证据落库、患者视图、中间件。
- 知识库为**演示数据**（10 sheet / 2556 条），未经医学审核。
